01 / what is an agent

A model that can act, remember and plan

A reasoning model thinks hard and then answers from what it already knows. An agent puts that model in a loop: think, use a tool, look at the result, think again. It can do things, it knows things beyond its training, and it plans its next step.

Who answers?

“I’m creative and love helping people. What careers fit, what programs get me there, and how do I pay for it?”

02 / tools and mcp

One plug shape for every tool

Tools let a model reach outside itself: call an API, run code, ask another model. The Model Context Protocol standardizes how that call travels. An MCP server offers tools, an MCP client calls them, and the result goes back into the model’s context. MCP fixes the transport and format, not the tool, so the same server works with any client.

03 / skills

Instructions that wait until they’re needed

A skill is a folder with a required SKILL.md, plus optional scripts and reference files. Only its short name and description sit in context at first. The full instructions load when a task actually calls for them. Skills complement MCP rather than replace it, and because they can contain executable code, only install them from sources you trust.

04 / retrieval augmented generation

Fetch only what this question needs

Context is finite and expensive. RAG ingests documents, chunks them, turns each chunk into a vector, stores it, and at question time retrieves the closest few by similarity and adds them to the prompt. A re-ranker takes a second, more careful pass over what was retrieved. The model gets relevant facts without the whole library, and it hallucinates less.

05 / short and long term memory

The model forgets. The agent decides what it keeps.

LLMs are stateless: on each call, the context window is everything the model knows. The agent carries a running state of goal, conversation, tool results and notes, and has to choose what fits. Anything older lives in long-term memory and is fetched back when needed.

06 / planning

A plan is a hypothesis

Without planning, agents lose the goal halfway through a multi-step task. Plan-then-execute writes every step up front and then runs them: fewer model calls, but slow to adapt. ReAct (reason + act, not the UI library) thinks after every observation, so it can change course when something breaks.

07 / reflection

Check the work, write down the lesson, try again

Self-refine has the model critique its own draft. Reflexion reacts to an outside failure, like a failed test, and writes a lesson learned for the next attempt. More rounds buy accuracy with latency and money, so the loop needs a hard stop. The checks you choose decide what “done” means.

10 / single agent systems

Let the model pick the arrows

ReAct, plan-and-execute and reflexion all run inside one agent loop. CodeAct changes what an action is: instead of one JSON tool call per turn, the agent writes a short program that calls several tools at once. Code is all over its training data; your custom tool schema isn’t. The catch: you are now running model-written code, so it belongs in a sandbox.

12 / evaluations

    
Right once, or right every time?

    
Leaderboards usually show one column, reliability, and hide cost and context. Many benchmarks run once. Two metrics tell different stories: pass@k asks whether at least one of k tries succeeds, and rises with k. pass^k asks whether all k succeed, and falls. Customer-facing agents live on pass^k.
